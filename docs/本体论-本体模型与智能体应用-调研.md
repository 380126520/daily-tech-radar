# 本体论、本体模型与智能体（Agent）应用 · 调研笔记

> 目标：讲清"本体论 / 本体模型"是什么、怎么建、为什么 LLM Agent 需要它、有哪些落地形态与代表工作，并给出可直接用于每日雷达追踪的关键词。
> 整理时间：2026-11-02；事实均附来源，区分"标准定义"与"一方研究结论"。

## 一、概念脉络：从哲学本体论到可计算的本体模型

### 1. 三个容易混的词

| 概念 | 定位 | 核心内容 |
| --- | --- | --- |
| 哲学本体论 (Ontology) | 形而上学分支 | 研究"存在/范畴"本身，世界由哪些基本类别的事物构成 |
| AI 本体 / 本体模型 (Ontology) | 知识工程的**模式层 (TBox)** | 对某领域概念化的**形式化、明确**规范：类、关系、属性、逻辑约束 |
| 知识图谱 (Knowledge Graph, KG) | 实例层 (ABox) | 按本体模式落地的实例事实网络，是本体定义的"物化/实例化" |

- **Gruber 经典定义**：本体是"概念化的明确规范"（an explicit specification of a conceptualization）。
- **Stanford《Ontology Development 101》(Noy & McGuinness)**：本体是对论域中概念（classes）、概念属性（slots/properties）及其约束（facets/restrictions）的形式化明确描述；**本体 + 一组实例 = 知识库**。["https://protege.stanford.edu/publications/ontology_development/ontology101-noy-mcguinness.html"]
- **W3C**：本体定义用于描述和表示某知识领域的术语，包含领域基本概念及其相互关系的计算机可用定义，供人、数据库、应用共享领域信息。["https://www.w3.org/TR/webont-req/"]

### 2. 本体 ≠ 分类法，本体 ≠ 知识图谱

- **vs 分类法 Taxonomy**：分类法只有"is-a"上下位层级（动物→哺乳动物→猫）；本体在此之上还有**多维关系、属性、逻辑约束**，并支持机器推理。
- **vs 知识图谱**：本体回答"这个领域允许存在哪些概念、什么关系合法"（schema）；知识图谱是填入的具体事实三元组网络。可理解为"KG 是符合本体定义的元素网络的物化"。["https://arxiv.org/html/2512.09596"]

### 3. 标准栈（W3C 语义网）

| 标准 | 作用 |
| --- | --- |
| RDF | 数据表达模型（主语-谓语-宾语三元组） |
| OWL | Web 本体语言，基于描述逻辑，提供形式语义与推理；OWL 1(2004) / OWL 2(2012) |
| SKOS | 简单知识组织系统，用于词库、分类表、叙词表 |
| SHACL | 实例图的**合规校验**（数据必须长什么样），与 OWL（可推理的开放世界语义）分工 |

> 关键区分：OWL 是**开放世界**语义——图里没提到某件事，不能直接断定它为假，因此 OWL 不适合当生产环境的"合规校验器"；运行时的数据合规/Agent 产出校验交给 SHACL。["https://leocavalcante.dev/en/ontologias-para-agentes-de-ia-o-contrato-que-falta-entre-modelo-memoria-e-ferramentas/","https://trustgraph.ai/guides/key-concepts/ontologies-holons-context-graphs/"]

## 二、本体怎么建（Ontology Development 101 流程）

1. **定边界与能力问题 (Competency Questions, CQ)**：先列"这个本体必须能回答哪些问题"，用 CQ 反推需要哪些概念，避免过度建模。
2. **复用优先**：查是否有现成标准本体 / Schema.org / 行业标准，不要重造轮子。
3. **列术语 → 建类层次**：抽出领域名词，组织成 is-a 分类树。
4. **定义关系与属性**：对象属性（object property，连接两个实例，如 `hasPart`、`causes`）、数据属性（data property，描述取值，如 `ratedVoltage`）。
5. **加约束**：基数、定义域/值域；公理交给 OWL 推理，实例合规交给 SHACL。
6. **填实例、迭代校验**，小步快跑，从核心概念起步。

**建模工具**：Protégé（Stanford 开源桌面本体编辑器）、RDF Studio、LinkML（模式交换格式）。
**LLM 辅助工具**：
- **OntoGPT / SPIRES**：零样本从自由文本抽取符合给定 schema 的嵌套语义结构，输出 JSON/YAML/RDF/OWL，Monarch Initiative 开源。["https://github.com/monarch-initiative/ontogpt","https://academic.oup.com/bioinformatics/article/40/3/btae104/7612230"]
- **OntoCast**：agentic、本体驱动的文档→语义三元组/KG 协同生成。["https://pypi.org/project/ontocast/0.2.2/"]
- **RIGOR**：RAG 驱动把关系库 schema 生成丰富 OWL 本体。["https://arxiv.org/html/2506.01232v1"]
- **HyDRA**：协作神经符号 Agent 先共同确定 CQ，再构建可验证 KG。["https://arxiv.org/html/2507.15917"]
- 综述见 *LLM-empowered knowledge graph construction: A survey*。["https://arxiv.org/html/2510.20345"]

## 三、为什么 Agent 需要本体：四个机制

LLM 的通病是词汇不统一、会幻觉、跨 Agent/工具/数据库语义对不齐、缺少硬约束。本体给 Agent 提供：

1. **共享词汇 / 语义契约**：人、多个 Agent、工具、数据库读同一套概念，省去每层翻译，被称为"模型、记忆与工具之间缺失的契约"。
2. **Grounding 接地**：把自由文本和检索结果锚定到受控概念上。OG-RAG 用本体组织文档超图、检索最小概念集合喂给 LLM，报告事实召回 +55%、响应正确率 +40%（论文自评，跨 4 个 LLM）。["https://arxiv.org/pdf/2412.15235"]
3. **运行时约束校验**：Agent 抽取/产出的三元组先过 SHACL，违反领域规则的关系直接拦截，保证图结构干净。
4. **可推理、可解释、可协作**：沿关系网络做规则推理，决策有据可溯；统一 schema 让多角色 Agent（抽取、对齐、冲突仲裁）协同。

## 四、结合形态（四类应用模式）

| 模式 | 做法 | 代表工作 |
| --- | --- | --- |
| A. LLM 自动建本体/填充 KG | 多 Agent 分工做实体发现、关系抽取、schema 对齐、冲突消解 | KARMA：9 个协作 Agent 从文献自动丰富 KG。["https://arxiv.org/html/2502.06472"] |
| B. 本体引导 RAG | 用本体组织/检索上下文，减少无关召回 | OG-RAG（本体接地 RAG） |
| C. 本体驱动多 Agent 协作 | 本体层编码领域规则，MCP/消息层同步，Agent 层路由执行 | 医疗：OWL/SWRL 本体层 + MCP 上下文同步 + MoE 路由。["https://dl.acm.org/doi/epdf/10.1145/3794209.3794236"]；工程设计：Graph Ontologist Agent 先建领域 KG，再交设计/系统工程师 Agent。["https://arxiv.org/html/2511.03179"] |
| D. 行业运维落地 | 设备/故障/缺陷建模为本体，支撑检索、推理、处置推荐 | 变电站 KG+GCN 故障识别；电力设备预测性维护知识图谱；NDT 检测规划多 Agent（KG 接地推理 + SHACL 校验计划一致性）。["https://academic.oup.com/ijlct/article/doi/10.1093/ijlct/ctag014/8501069","https://www.aliyun.com/solution/energy/powerequipment","https://ceur-ws.org/Vol-4104/paper2.pdf"] |

## 五、落地建议（结合电力巡检场景）

- 不要上来建"大而全"本体：从一批**能力问题**出发（如"某绝缘子在某电压等级下出现某缺陷，可能原因、历史处置、相邻部件"），先建最小核心本体。
- 分层：本体(schema)管概念与规则，SHACL 管实例/Agent 产出合规，KG 存事实，LLM 负责自然语言接入与抽取，人审一致性。
- 与现有视觉检测衔接：缺陷类别、设备部件、工况作为本体类，检测结果作为实例，可向上做缺陷原因推理和处置推荐，而非只停留在"检出一张图"。
